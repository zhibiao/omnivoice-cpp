# OmniVoice 语音克隆全流程

本文描述 OmniVoice 从「参考音频 + 参考文本 + 目标文本」到「输出 WAV」的完整执行路径，
覆盖 CLI 入口、模型加载、Voice Prompt 构建、扩散式语音码生成、音频解码和后处理。

- 参考音频：24 kHz 单声道 WAV 或 MP3，其他容器直接报错。
- 输出音频：24 kHz 单声道，最终写成 16-bit PCM WAV。
- 采样契约：整条链路固定 24 kHz；音频码率 25 Hz（每帧 960 样本），8 个 codebook。

---

## 1. 一句话概览

```
参考音频 ──► Higgs Encoder ──► RVQ ──► 8×N 音频码 ──► .ovprompt
                                                        │
目标文本 ──► 文本切分 ──► Prompt 拼接 [style|text|reference|target]
                                                        │
                                                        ▼
                              28 层 Qwen3 双向扩散 LM（32 步，CFG）
                                                        │
                                                        ▼
                                            8×M 目标音频码
                                                        │
                                                        ▼
                               Higgs Decoder ──► 24 kHz 波形 ──► 后处理 ──► WAV
```

代码上分两个对外 API：

| API | 作用 | 产物 |
|---|---|---|
| `OmniVoiceModel::create_prompt` | 参考音频 → 可复用的说话人 prompt | `VoiceClonePrompt` / `.ovprompt` |
| `OmniVoiceModel::generate_voice_clone` | prompt + 文本 → 音频 | `VoiceCloneOutput` / WAV |

`create_prompt` 只跑一次编码器；`generate_voice_clone` 每次生成都重新构造 LM prompt 并跑扩散。

## 2. 固定契约与关键常量

这些值在加载时由 GGUF 元数据读出，并在 `src/config.cpp` 里做一致性校验。

| 常量 | 值 | 来源 |
|---|---|---|
| 采样率 | 24000 | `audio_tokenizer.sample_rate` |
| hop length | 960 | `audio_tokenizer.hop_length` |
| 帧率 | 25 Hz | `24000 / 960` |
| codebook 数 | 8 | `lm.num_audio_codebooks` |
| codebook 大小 | 1024 | `audio_tokenizer.codebook_size` |
| codebook 维度 | 64 | `audio_tokenizer.codebook_dim` |
| 音频词表 | 1025 | `lm.audio_vocab_size` |
| MASK id | 1024 | `lm.audio_mask_id` |
| LM hidden | 1024 | `llm.hidden_size` |
| LM 层数 | 28 | `llm.num_hidden_layers` |
| 注意力头 | 16 / KV 8，head_dim 128 | `llm.*` |
| 文本词表 | 151676 | `llm.vocab_size` |

**音频词表为什么是 1025**：1024 个真实码 + 1 个 MASK。MASK 只出现在扩散输入里，
生成结束前必须全部被替换掉（`diffusion_decoder.cpp` 末尾会检查）。

**音频嵌入是共享的**：`audio_embeddings.weight` 形状是 `[hidden, 8 × 1025]`，
第 `c` 个 codebook 的 token `t` 使用行 `t + c × 1025`。8 个 codebook 的嵌入相加后
作为该位置的音频嵌入（`qwen3_model.cpp:808-816`）。

## 3. 模型加载

入口：`OmniVoiceModel::load(lm_gguf, audio_gguf, params)`（`src/omnivoice.cpp:67`）。

```
GGMLSession.init(device)          // 注册 backend，CPU 或 CUDA
  │
  ├─ GGUFModel::open(lm)          // 312 个 tensor
  ├─ GGUFModel::open(audio)       // tokenizer 权重
  ├─ load_omnivoice_config()      // 读 LM / tokenizer / generation 元数据
  ├─ TextTokenizer.load()         // BPE + added tokens
  ├─ OmniVoiceLM.load()           // 权重上传，打包 qkv
  ├─ HiggsAudioEncoder.load()     // 语义 + 声学编码器权重
  └─ HiggsAudioDecoder.load()     // 上采样解码器权重
```

`OmniVoiceModel::Impl` 的成员顺序是刻意安排的（`src/omnivoice.cpp:49-59`）：

```cpp
struct OmniVoiceModel::Impl {
    GGMLSession session;                    // 最先构造，最后析构
    std::unique_ptr<GGUFModel> lm_gguf;
    std::unique_ptr<GGUFModel> audio_gguf;
    OmniVoiceConfig config;
    TextTokenizer tokenizer;
    std::unique_ptr<OmniVoiceLM> lm;        // 借用 backend
    std::unique_ptr<HiggsAudioEncoder> encoder;
    std::unique_ptr<HiggsAudioDecoder> decoder;
    bool loaded = false;
};
```

子模型只**借用** `session.backend()`，不拥有它；因此 backend 必须比它们活得久。
声明顺序保证析构时子模型先释放、backend 后释放。

### 生成参数从哪来

`VoiceCloneConfig` 全部来自 LM GGUF 的 `omnivoice.generation.*`（`src/config.cpp:514`）：

| 字段 | 默认/元数据 | 作用 |
|---|---|---|
| `num_step` | 32 | 扩散步数 |
| `guidance_scale` | 2.0 | CFG 强度 |
| `t_shift` | 0.1 | mask 调度曲线偏移 |
| `layer_penalty_factor` | 5.0 | codebook 层级惩罚 |
| `position_temperature` | 5.0 | 位置维 Gumbel 温度 |
| `class_temperature` | 0.0 | 0 表示走融合确定性采样 |

| `audio_chunk_duration` | 15.0 s | 长文本单块目标时长 |

`t_shift` 与 PyTorch 参考实现一致，是**速度/质量旋钮**，不是精度问题。

## 4. 阶段 A：参考音频 → Voice Prompt

### 4.1 CLI 入口

`--create-prompt`（`app/omnivoice_cli.cpp:402`）：

```
omnivoice-cli --create-prompt \
  --model models/omnivoice-lm-f16.gguf \
  --audio-tokenizer models/omnivoice-tokenizer-f32.gguf \
  --ref-audio assets/nana.wav \
  --ref-text assets/nama.txt \
  --prompt-output voices/nana.ovprompt \
  --device CUDA0
```

`--ref-text` 以 `.txt` 结尾时按 UTF-8 文本文件读取（自动去 BOM 和尾部换行），
否则直接当字符串使用（`app/omnivoice_cli.cpp:160`）。

### 4.2 读取音频

`load_audio_24k_mono`（`src/audio_toolkit/audio_loader.cpp`）先按文件头嗅探容器：

| 容器 | 处理 |
|---|---|
| `RIFF....WAVE` | `load_audio` 按原生采样率和通道数解析（PCM16/24/32、float32、`WAVE_FORMAT_EXTENSIBLE`），再降混为单声道并用 `resample_audio` 转到 24 kHz |
| `ID3` / MPEG frame sync | miniaudio 解码为原生采样率/通道数的 f32，再走同一套降混 + 重采样 |
| 其他 | 报错 `unsupported audio format (expected WAV or MP3)` |

`load_audio`（`src/audio_toolkit/audio_loader.cpp`）只负责解码，原样返回文件里的采样率、
通道数和交错 f32 样本，不做降混或重采样。重采样在
`src/audio_toolkit/audio_resampler.cpp`：Hann 窗 sinc、`lowpass_filter_width = 6`、
`rolloff = 0.99`，与 torchaudio 的 `sinc_interp_hann` 一致，支持
8 / 11.025 / 16 / 22.05 / 32 / 44.1 / 48 / 88.2 / 96 / 192 kHz 等常见采样率到 24 kHz，
多声道逐声道独立滤波。文件大小有上限，空文件报错。

### 4.3 预处理

`create_voice_clone_prompt`（`src/voice_clone_prompt.cpp:146`）：

1. `validate_audio_24k_mono`：必须非空、24 kHz、单声道。
2. 参考文本不能为空。
3. 计算**原始 RMS** 并记录到 `prompt.reference_rms`（后处理会用到）。
4. 如果 `0 < RMS < 0.1`，整体乘以 `0.1 / RMS`，把参考音频抬到约 0.1 RMS 再做编码。
5. `preprocess_reference == true` 时去静音：阈值 −50 dBFS、最短静音 200 ms、保留 100 ms。

注意第 3 步记录的是**增益前**的 RMS，第 4 步只影响送进编码器的副本。

### 4.4 Higgs Encoder

`HiggsAudioEncoder::encode`（`src/higgs_tokenizer/encoder.cpp:1121`）是一条双分支图：

```
                 ┌─ 24k → 16k 重采样 ─► 语义分支（HuBERT 风格，12 层）
参考波形 24 kHz ─┤                          │
                 └─ 声学分支（DAC 风格，5 个 stride 块）
                                            │
                                    按帧对齐后 concat
                                            │
                                      fc 投影到 512
                                            │
                                    8×N 连续嵌入
```

细节：

- **语义分支**：`24 kHz → 16 kHz`（`resample_24k_to_16k`，实现见
  `src/audio_toolkit/audio_resampler.cpp`，匹配 torchaudio 的
  `sinc_interp_hann`），首尾各补 160 个零（总长 +320）；7 层卷积特征提取（stride 5 后接 6 个 stride 2），
  再经过 12 层 HuBERT block。每层是 `attention + layer_norm + FFN + final_ln`，
  注意力用 `ggml_flash_attn_ext`，mask 全 0（**双向、无因果**）。
  13 个隐状态取平均后做一次 2× 下采样，再进语义编码器（2 个 block × 2 个残差单元）。
- **声学分支**：直接在 24 kHz 上跑，5 个 block 的 stride 为 `{8, 5, 4, 2, 3}`，
  总下采样 960；每个 block 前 3 个残差单元（dilation 1/3/9），用 Snake 激活。
- 两分支帧数必须相等，否则报 `Higgs semantic/acoustic frame count mismatch`。
  声学分支帧数不足时会在首尾各补 480 个零（总长 +960）再编码。
- 拼接后 `fc` 投影，输出 `[frames, 512]`（时间优先），转成时间主序后交给量化器。

一次编码的帧数约为 `样本数 / 960`（按各层卷积的输出长度公式计算），例如 6.04 s 参考音频 ≈ 151 帧。

### 4.5 RVQ 量化

`quantize_residual`（`src/higgs_tokenizer/encoder.cpp:836`）是纯 CPU 的残差向量量化：

```
residual = embeddings
for c in 0..7:
    projected = pin_c(residual)              # 512 → 64
    code[c]   = argmin_e ||projected - cb_c[e]||²   # e ∈ [0, 1024)
    residual -= pout_c(cb_c[code[c]])        # 64 → 512
```

输出 `AudioCodes`：`codebooks = 8`、`frames = N`、`data` 按 **codebook-major**
排列，即 `data[c * frames + t]`。每个码都必须在 `[0, 1024)`。

### 4.6 `.ovprompt` 文件格式

`save_voice_clone_prompt` / `load_voice_clone_prompt`（`src/voice_clone_prompt.cpp:202/260`），
全部小端：

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 8 | magic `OVPROMPT` |
| 8 | 4 | version = 1 |
| 12 | 4 | sample_rate（必须 24000） |
| 16 | 4 | codebooks（必须 8） |
| 20 | 4 | frames |
| 24 | 4 | reference_rms（f32） |
| 28 | 4 | flags（bit0 = denoise） |
| 32 | 4 | language 字节数 |
| 36 | n | language（UTF-8） |
| … | 4 | reference_text 字节数 |
| … | m | reference_text（UTF-8） |
| … | `frames × codebooks × 4` | i32 音频码，codebook-major |

加载时的强校验：

- magic / version 必须匹配；
- `sample_rate == 24000`、`codebooks == 8`、`frames > 0`；
- 码值必须在 `[0, 1024)`；
- 不允许尾部多余字节；
- 文本、语言、码数量都有上限，防止损坏文件撑爆内存。

> 注意：`.ovprompt` 里保存了 `denoise` 标志，但**生成时实际生效的是本次请求的
> `denoise`**（`request.denoise`），它决定 style 段是否插入 `<|denoise|>`。
> 复用 prompt 时如果不显式传 `--denoise`，会取 GGUF 的默认值。

## 5. 阶段 B：Prompt + 文本 → 音频

入口：`OmniVoiceModel::generate_voice_clone`（`src/omnivoice.cpp:297`）。

### 5.1 目标帧数决策

优先级从高到低：

1. `request.duration_seconds > 0` → `frames = max(1, int(duration × 25))`（截断取整）
2. `request.target_frames > 0` → 直接用
3. 否则 `estimate_target_frames(...)`（`src/duration_estimator.cpp:318`）

估计器是**规则法**，不跑模型：

```
reference_weight = Σ 每个参考字符的权重
target_weight    = Σ 每个目标字符的权重
speed_factor     = reference_weight / reference_frames
duration_frames  = target_weight / speed_factor
frames           = max(1, int(duration_frames / speed))
```

字符权重（`src/duration_estimator.cpp:187-255`）：

| 类别 | 权重 |
|---|---|
| ASCII 字母 | 1.0 |
| 空格 / 分隔符 | 0.2 |
| 组合记号 / 阿拉伯 tatweel | 0.0 |
| 标点 / 符号 | 0.5 |
| 数字 | 3.5 |
| CJK | 3.0 |
| 韩文 | 2.5 |
| 假名 | 2.2 |
| 埃塞俄比亚文 / 彝文 | 3.0 |
| 印度系 / 高棉-缅甸 | 1.8 |
| 泰-老 / 阿拉伯 / 希伯来 | 1.5 |
| 其他 | 1.0 |

参考为空或帧数 ≤ 0 时，用 `"Nice to meet you."` / 25 帧兜底。

> 该估计只决定**生成多长**，不决定音质。文本里数字权重高，是因为数字通常读成多个音节。

### 5.2 长文本切分

`plan_text_chunks`（`src/text_tokenizer/text_chunker.cpp:164`）：

```
threshold_frames = max(1, int(audio_chunk_threshold × 25))   # 30 s → 750 帧
if estimated_frames <= threshold_frames:
    单块，直接返回
else:
    chars = UTF-8 码点数
    tokens_per_char = estimated_frames / chars
    chunk_chars = max(1, int(audio_chunk_duration × 25 / tokens_per_char))
    chunk_text_punctuation(text, chunk_chars, min=3)
```

切分器会：

- 按 `. , ; : ! ?` 及全角版本切句；
- 识别常见缩写（`Mr.`、`e.g.`、`No.` 等）避免误切；
- 把右引号、右括号等收尾符号并入前一句；
- 把短句合并到不超过 `chunk_chars`；
- 小于 3 个码点的尾块并入前一块（第一块过短时特殊处理）。

多块时每个 chunk 会**重新估计**自己的目标帧数，并使用 `seed + chunk_index` 作为随机种子，
保证多块之间不完全相同但可复现。

### 5.3 Prompt 构造

`build_voice_clone_prompt`（`src/prompt_builder.cpp:320`）把序列拼成四段：

```
[ style | text | reference | target ]
    45（合计）      151 帧      113 帧
```

以一次实测为例：`45 + 151 + 113 = 309`。

#### style 段

```
"<|denoise|>"? + "<|lang_start|>" + language + "<|lang_end|>"
              + "<|instruct_start|>None<|instruct_end|>"
```

- `denoise` 为真才加 `<|denoise|>`；
- `language` 为空或 `"none"`（大小写不敏感）时归一化为 `"None"`；
- 目前 instruct 固定为 `None`。

#### text 段

```
"<|text_start|>" + encode(reference_text + " " + target_text) + "<|text_end|>"
```

拼接前会做文本规范化（`combine_reference_target_text`）：

1. 两端去空白；
2. 中间用一个空格连接；
3. 删除 `\r`、`\n`；
4. 全角括号 `（）` 转 ASCII `()`；
5. 连续空格/制表符合并；
6. 删除 CJK 字符两侧的空格。

BPE 编码时会先识别 13 个非语言标签，整段作为 special token 编码，不会被拆开：

```
[laughter] [sigh] [confirmation-en] [question-en] [question-ah] [question-oh]
[question-ei] [question-yi] [surprise-ah] [surprise-oh] [surprise-wa]
[surprise-yo] [dissatisfaction-hnn]
```

分词器**不额外添加 BOS/EOS**，只有这里显式写入的 special token。

#### reference 段

直接把 `.ovprompt` 的 8×N 码原样填入。

#### target 段

全部填 `audio_mask_id`（1024），等待扩散模型填充。

#### 布局与张量

`PromptPlan`（`src/prompt_builder.h:23-41`）：

```cpp
style_frames   = style_tokens.size()
text_frames    = text_tokens.size()
reference_start = style_frames + text_frames
target_start    = reference_start + reference_codes.frames
sequence_length = target_start + target_frames
```

- `input_ids`：`[8, sequence_length]`，初始全为 MASK；
  逐 codebook 把 style / text / reference 三段拷进去，target 段保持 MASK。
- `audio_mask`：每个位置 1 字节；style 和 text 为 0，reference 和 target 为 1。
  LM 用它决定该位置取文本嵌入还是音频嵌入。

### 5.4 扩散解码

`run_diffusion_decoder`（`src/diffusion_decoder/diffusion_decoder.cpp:73`）是整条链路的核心。

#### 5.4.1 mask 调度

`build_mask_schedule`（`src/diffusion_decoder/mask_schedule.cpp:39`）：

```
s_i = i / num_steps
t_i = t_shift * s_i / (1 + (t_shift - 1) * s_i)      i = 0..num_steps

count_i = ceil(total × (t_{i+1} - t_i))              i < num_steps - 1
count_last = 剩余全部
```

其中 `total = 8 × target_frames`。`t_shift = 0.1` 时曲线是「前慢后快」：
开头每步只解几个格子，最后一步解掉一大片。

实测 `total = 904`、32 步的每步数量：

```
3, 4, 4, 4, 4, 4, 5, 5, 5, 6, 6, 7, 7, 8, 9, 9,
10, 11, 13, 14, 16, 19, 21, 25, 30, 36, 44, 56, 73, 99, 142, 205
```

总和 904。最后一步 205 个格子，占总量的 22.7%。

#### 5.4.2 条件与无条件输入

CFG 需要两条输入：

| | 条件分支 | 无条件分支 |
|---|---|---|
| 序列长度 | 309（完整 prompt） | 113（只有 target） |
| `target_start` | 196（45 + 151） | 0 |
| `input_ids` | style+text+reference+当前 target | 只有当前 target |
| `audio_mask` | style/text=0，其余=1 | 全 1 |

无条件分支只保留目标区域的当前码，用来估计「没有参考和文本时会怎么预测」，
两者相减就是 CFG 的引导方向。

#### 5.4.3 打包 LM 图

`OmniVoiceLM::init_diffusion_graph` 构建一张固定形状的图，两条分支拼在一起：

```
条件分支 (309) ─┐
                ├─ concat 到 422 个位置 ─► 28 × packed Qwen3 block ─► rms_norm
无条件分支 (113) ┘
                                                    │
                                   各自切出 target 区域 (113)
                                                    │
                                    audio_heads → [8×1025, 113]
```

每个位置的输入嵌入：

```
text_emb  = embed_tokens[text_id]                  # 文本词表
audio_emb = Σ_{c=0..7} audio_embeddings[token_c + c × 1025]
hidden    = text_weight × text_emb + audio_weight × audio_emb
```

`text_weight` / `audio_weight` 由 `audio_mask` 决定：非音频位置文本权重 1、音频权重 0，
反之亦然。位置 id 是分支内从 0 开始的连续整数。

packed block 的注意力是**两次独立的双向注意力**（`src/qwen3_lm/qwen3_block.cpp:349`）：
先按 `first_sequence_length = 309` 切成两段，各自 `attention(..., mask = nullptr)`，
再 concat 回去。也就是说两条分支互不可见，但每条分支内部是全可见的（非因果）。

输出头的计算（`src/qwen3_lm/qwen3_model.cpp:885-960`）：

```
cond_logits = audio_heads(cond_target_hidden)      # [8200, 113]
uncond_logits = audio_heads(uncond_target_hidden)

cond_lp   = log_softmax(cond_logits)
uncond_lp = log_softmax(uncond_logits)
guided    = cond_lp + guidance × (cond_lp - uncond_lp)
guided_lp = log_softmax(guided)

masked = guided_lp + token_mask        # MASK 位置加 -inf
pred   = argmax(masked)                # 每个格子一个 token
conf   = max(masked)                   # 该 token 的 log 概率
```

`class_temperature == 0`（默认）时走这条**融合确定性路径**：
argmax 和 max 都在 GPU 图上完成，只把 `[8×113]` 的预测和置信度拷回主机。
只有 `class_temperature > 0` 时才把 `[8×113×1025]` 的完整 logits 拷回主机做 Gumbel 采样。

#### 5.4.4 采样与提交

每步流程（`diffusion_decoder.cpp:163-275`）：

```
1. 把当前 target 码写进两条分支的 audio_ids
2. 前向一次打包图，得到 904 个格子的 pred / conf
3. TokenSelector::select_scored:
      score[cell] = conf - codebook × layer_penalty_factor
      对仍是 MASK 的格子加 Gumbel 噪声（temperature = position_temperature）
      非 MASK 格子 score = -inf
      top_k = counts[step]，取 score 最大的 top_k 个格子
4. 把选中格子的 pred 写回 current，同时写回条件分支的 input_ids
5. 统计剩余 MASK 数
```

几个关键点：

- **层级惩罚**：codebook 越靠后，`-c × 5.0` 越大，倾向于先确定低层 codebook。
- **位置温度**：Gumbel 噪声让每一步选中的格子不完全等同于「置信度最高的格子」，
  避免同一区域被连续解锁。
- **top_k 恰好等于调度数量**，所以 32 步后所有格子都被填满；
  如果还有 MASK 会直接报错。
- 选中格子的 token 会立刻写回条件分支，下一步就能看到已确定的码；
  无条件分支每步只用 `current` 重建，不保留历史。

图只在形状变化时重建；`generate_chunk` 每块结束后会调用
`release_diffusion_graph()`，所以多 chunk 场景每块都会重建一次图。

### 5.5 音频解码

`decode_codes` → `HiggsAudioDecoder::decode`（`src/higgs_tokenizer/decoder.cpp:919`）。

```
8 × I32 码 (113)
      │
      ├─ 每个 codebook: cb.embed[code] → pout 投影到 256，再全部相加
      ▼
    quantized [256, 113]
      │
    fc2 → 1024
      │
    conv1（时间维 1D 卷积，padding 保持帧数）
      │
    5 个上采样 block，stride = {8, 5, 4, 2, 3}
      每个 block: Snake → 转置卷积 → 3 个残差单元（dilation 1/3/9）
      ▼
    Snake → conv2
      ▼
    24 kHz 波形，长度 = frames × 960 = 113 × 960 = 108480
```

- 上采样倍率乘积 `8×5×4×2×3 = 960`，正好等于 hop length。
- GPU 上转置卷积走「矩阵乘 + 相位拼接」路径，权重在加载时做过重排；
  CPU 上走 `ggml_conv_transpose_1d`。
- 解码图按 `frames` 缓存：同一帧数复用，帧数变化才重建。
- 输出是 `AudioBuffer{sample_rate = 24000, channels = 1}`。

### 5.6 多 chunk 拼接

只有 `chunks.size() > 1` 时才执行 `cross_fade_audio_chunks`
（`src/audio_toolkit/audio_processing.cpp`），固定参数：

```
total_fade = 0.3 s × 24000 = 7200 样本
fade       = 7200 / 3 = 2400 样本
silence    = 2400 样本
```

对每个后续 chunk：

1. 前一块最后 2400 样本线性淡出到 0；
2. 插入 2400 个零样本；
3. 本块前 2400 样本线性淡入；
4. 追加。

总长 = 各块长度之和 + `(块数 − 1) × 2400`（淡入淡出不改变长度，只加静音）。

### 5.7 后处理

`postprocess_generated_audio`（`src/audio_toolkit/audio_processing.cpp`），顺序固定：

1. **硬限幅**：`clamp(sample, -1, 1)`。
2. **去静音**（仅 `postprocess_output == true`）：
   阈值 −50 dBFS、最短静音 500 ms、保留 100 ms。
   全静音会报错。
3. **RMS 匹配**：如果 `reference_rms < 0.1`，整体乘以 `reference_rms / 0.1`。
   这是为了保持参考音频的响度；参考 RMS ≥ 0.1 时不做增益。
4. **首尾淡入淡出**：各 0.1 s（2400 样本），线性。
5. **首尾补零**：各 0.1 s（2400 样本）。

注意第 2 步会**缩短**音频，第 5 步再**加长**；所以最终长度不等于
`frames × 960`，而是去静音后的长度 + 4800。

### 5.8 写 WAV

CLI 在写盘前再做一次 `clamp`（`app/omnivoice_cli.cpp:600-606`），
然后 `save_wav_24k_mono` → `write_wav`（`src/audio_toolkit/audio_writer.cpp`）：

- 只接受 24 kHz 单声道（`save_wav_24k_mono` 会校验）；
- 16-bit PCM，小端；
- 标准 44 字节 RIFF/WAVE 头；
- 路径按 UTF-8 处理，Windows 下用 `wmain` 转成 UTF-8 再解析参数。

## 7. 性能分解

单次生成（4.72 s 音频、32 步）：

| 阶段 | 时间 | 说明 |
|---|---|---|
| 模型加载 | ~2.2 s | 一次性，与文本无关 |
| Prompt 构造 | 几 ms | BPE + 张量填充 |
| 扩散 LM | 32 × 42–44 ms ≈ 1.35–1.4 s | 占总时间约 88% |
| Token 选择 | 0.02–0.03 ms/步 | 可忽略 |
| 音频解码 | 约 0.1 s 量级 | 与帧数成正比；由总时长减去扩散时间推算 |
| 后处理 | 几 ms | 纯 CPU 遍历 |

结论：

- **扩散步数是唯一的主要成本**，每步成本由图形状（`8 × target_frames`、`309 + 113` 位置）
  固定，所以 `总时间 ≈ num_step × 单步时间`。
- `--num-step` 是唯一无需改代码的速度旋钮；减步会改变听感，需要 A/B。
- `t_shift` 只改变每步解锁多少格子，不改变单步成本。
- 单步 42–44 ms 对应约 413 GFLOP，约 9.3 TFLOPS；PyTorch 参考约 12.2 TFLOPS，
  差距主要来自 ggml 的 GEMM 分组和拷贝节点，而不是调度。

## 8. 边界与错误处理

| 场景 | 行为 |
|---|---|
| 参考音频非 WAV/MP3 | `unsupported audio format (expected WAV or MP3)` |
| 参考音频非 24 kHz / 非单声道 | WAV 走 miniaudio 转换；MP3 直接解码到 24 kHz 单声道 |
| 参考文本为空 | `reference text is empty` |
| 目标文本为空 | `target text must not be empty` |
| `speed <= 0` | `speed must be positive` |
| `duration < 0` 或非有限 | 报错 |
| 目标帧 ≤ 0 且估计失败 | 报错 |
| `.ovprompt` 损坏 / 版本不符 / 尾部多余 | 拒绝加载 |
| 码值越界 | 拒绝 |
| 扩散结束仍有 MASK | `diffusion decoder left target cells masked` |
| 采样器给出 MASK 或越界 token | 报错 |
| 全静音参考 / 全静音输出 | `remove_silence` 报错 |
| 输出路径为空 / 采样率非正 | WAV 写入报错 |
